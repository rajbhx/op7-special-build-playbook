# A19 — local llama.cpp init fails on-device: 'no backends are loaded'

**Section**: A. CI & build pipeline
**Keywords**: android, apk, backends, build, contended, default, empty, exec, extractnativelibs, fails, false, ggml, ggml_backend_load_all, ggml_backend_load_all_from_path, init, jni, llama.cpp, llama_backend_init, loaded, local, nativelibrarydir, on-device, packs, pipeline, q4_k_m, qwen0.5b, searched, true, verified

## Problem

local llama.cpp init fails on-device: 'no backends are loaded'

## Root cause

AGP default extractNativeLibs=false packs .so in APK so nativeLibraryDir is empty; ggml_backend_load_all() searched exec dir + cwd only

## Solution

android:extractNativeLibs=true + ggml_backend_load_all_from_path(nativeLibraryDir) before llama_backend_init; verified on-device init OK (RSS 729 MB, Qwen0.5B Q4_K_M, contended)
