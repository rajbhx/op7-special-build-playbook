## Problem

router health state was reset every run — each runAgent/sendQuick built a fresh ModelRouter with a new ProviderHealthMonitor, so repeated failures never accumulated and measured latency was ignored

## Root cause

health monitor defaulted inside ModelRouter instead of being shared

## Solution

EngineViewModel owns one ProviderHealthMonitor; routers are constructed with it; reportLatency + reportSuccess/reportFailure recorded per run; router sort adds measured latency as tiebreak (nulls last, never fabricated)
