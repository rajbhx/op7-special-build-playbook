## Problem

agent fallback silently swapped the user's model kind: a failed local pick could be replaced by a free remote (whose anonymous rate-limit error then appeared as if the user chose it)

## Root cause

ThinkingAgent fallback called router.route(task, registry, excludeIds) with no kind preference; ModelRouter had no preferKind seam; sendQuick showed raw provider errors

## Solution

ModelRouter.route gained preferKind (same-kind candidates tried first, full pool only when none remain); ThinkingAgent passes the failed model's kind and always emits an honest Routed(reason); VM translates known provider errors (rate-limit/401/timeout/network) into actionable text
