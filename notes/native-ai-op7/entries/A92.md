## Problem

no real follow-up continuity: every send started a new session, answers were only saved on AgentEvent.Final, and stopped/failed runs broke the thread

## Root cause

EngineViewModel created a fresh session per run and ended it in finally; sendQuick never persisted; priorConversation read recentMessages() in DESC order

## Solution

one activeSessionId reused by sendQuick + runAgent (Clear closes it = new conversation); exchange saved on success, error and stop; MemoryDatabase.conversationTail() returns chronological order for prior-turn context
